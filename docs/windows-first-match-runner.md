# Windows 首场匹配运行器

> 当前范围：`2560x1440`、中文、全屏；新手任务已经完成、只能进入首场匹配的账号。

新账号训练是另一套任务配置，见 [Windows 新号训练任务运行器](windows-first-tutorial-runner.md)。两者复用常驻监督器、证据记录、前台守卫和安全清障，但不混用训练动作与匹配动作。

## 已实现流程

当前提供两个真实输入入口：

- `start --mode match`：新的常驻监督器，从任意已标定画面接管；前台丢失、黑屏、未知画面和输入未确认都转为可恢复暂停，并启动本地状态控制台。
- `live`：旧的固定顺序首场流程，仅保留用于回归比较。

```text
识别“继续”并点击
  → 识别大厅“准备”并点击
  → 英雄选择页不输入，等待自动选择
  → 识别“是跳伞指挥官”后不按 LCTRL，等待可发射
  → 出现“E 发射”后点按 E
  → 识别自由落体速度尺，释放本程序持有的全部输入
  → 连续三帧识别地面 HUD
  → 等待画面稳定并保存最终截图
```

程序不读游戏内存、不注入进程，也不尝试隐藏输入。它只对完整屏幕帧中的固定 ROI 做模板识别，然后使用 Windows `SendInput` 发送两次鼠标点击和必要的键盘点按。

## 第一次安装

在 Windows PowerShell 中进入项目的 `windows` 目录：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\setup.ps1
```

如果当前窗口是 `cmd.exe`（提示符形如 `C:\...>`），不要直接执行 `Set-ExecutionPolicy`，使用下面这条兼容命令：

```bat
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1
```

先运行纯离线验证：

```powershell
.\run.ps1 validate
```

它应对七张原图全部输出 `PASS`，且不会发送系统输入。

## 推荐的真实验证

1. 将 Windows 分辨率设为 `2560x1440`，Apex 设为中文全屏。
2. 启动 Apex；可以停在“继续”、大厅、英雄选择、运输舰、可发射、自由落体或已落地中的任一已标定画面。
3. 在终端执行：

```bat
powershell -NoProfile -ExecutionPolicy Bypass -File .\run.ps1 start --mode match
```

4. 先在 Windows 浏览器打开终端打印的 `http://127.0.0.1:8765`，可以查看状态、关键截图和事件，也可以暂停、继续、停止或紧急释放输入。
5. `Alt+Tab` 回 Apex。该入口没有容易错过的倒计时：终端或浏览器在前台时显示 `PENDING_FOREGROUND`，Apex 恢复前台后等待 700ms，再从当前画面重新识别。

只有前台进程名为 `r5apex.exe` 或 `r5apex_dx12.exe` 时程序才允许发送输入。任何时候按 `F8` 都会紧急停止；也可以在终端按 `Ctrl+C` 正常结束。

监督器的恢复规则：

- Apex 失去前台：立即释放输入并进入 `FOREGROUND_PAUSED`，切回后重新识别，不沿用旧动作。
- 近黑帧：进入 `LOADING` 并继续观察。
- 连续 5 秒没有命中模板：进入低频 OCR；OCR 约每 2 秒读取外置字典指定的 ROI，连续命中两次才接受。字典未命中时进入 `UNKNOWN_PAUSED`，保存一张证据图并继续低频重试，不点击未知页面。
- 点击或按键没有后置画面确认：只做有限重试；当前跳伞指挥官样本不会发送 `LCTRL`。
- 已落地：降低到约 1.5 秒一次观察；阶段 A 不发送近战、移动等局内行为。

OCR 字典位于 `windows/config/obstacle-rules.zh-CN.json`。目前只定义了“升级后继续”“奖励后继续”“公告关闭”三类候选，识别和消除严格分开：清障只允许 `Enter` 或 `Esc` 等键盘动作，不用 OCR 坐标点击按钮。

默认命令是**观察模式**：即使 OCR 连续识别到安全障碍，也只留证和暂停，不发送清障输入。晚上第一次验证建议先用默认命令。确认网页中的 OCR 规则和画面确实一致后，再停止任务并显式武装：

```bat
powershell -NoProfile -ExecutionPolicy Bypass -File .\run.ps1 start --mode match --arm-safe-obstacles
```

武装只影响外置字典里已经声明为安全页的键盘动作；未知页仍然不会盲按。动作后若没有进入加载或已知页面，达到规则上限后会进入 `ACTION_PAUSED`，不会无限重试。

正常菜单和跳伞阶段约每 300ms 观察一次；落地后约 1.5 秒一次；未知/OCR 页面约 2 秒一次。普通帧只在内存中使用，只有状态变化、OCR 障碍和未知证据等关键画面落盘。网页显示的是最近一张关键截图，不是持续视频流。

每次运行证据保存在：

```text
windows/runs/<时间>/
├── actions.jsonl
├── events.jsonl
├── status.json
├── result.json       # 任务停止后生成
└── screenshots/
```

`windows/runs/status.json` 是当前会话状态的固定入口，可直接读取，不需要先寻找最新时间目录。写入采用临时文件替换，读取方不会看到半截 JSON。

如果需要复现旧的严格线性行为，仍可执行：

```powershell
.\run.ps1 live
```

它要求在 5 秒倒计时内切回 Apex，且超时或前台丢失仍会结束；不要把它与新的常驻入口混用。

## 今晚验证清单

1. 先执行 `validate`，确认七张模板和 `OCR 引擎` 全部 `PASS`。
2. 用默认、不带 `--arm-safe-obstacles` 的命令启动；打开本地网页后切回 Apex。
3. 从“继续”页观察到大厅、英雄选择、运输舰、`E` 发射、自由落体和落地；中途主动切出一次，再切回，任务应恢复而不是退出。
4. 如果出现奖励、升级或公告页，网页应显示 OCR 规则；默认模式不应自动按键。
5. 只有确认 OCR 规则正确后，才停止并加 `--arm-safe-obstacles` 重跑清障。
6. 碰到未覆盖画面时保留该次 `windows/runs/<时间>/`；未知截图会在 `screenshots/`，可用于下一轮标定。

## 当前限制

- 只标定了用户提供的一个赛季界面和首场匹配链路；UI 更新后应重新采样。
- 奖励、升级和公告已有 OCR 规则与安全执行框架，但还没有用真实障碍截图标定；因此默认不武装，不能把离线字典测试描述成真实游戏验证。送箱子若没有命中字典仍会进入 `UNKNOWN_PAUSED`。
- 本地语义分类器和 AI 视觉兜底尚未实现。计划外页面不会让进程退出，但也不会被“智能猜测”后自动操作；它会留证、释放输入并暂停观察。
- 已新增独立的 `tutorial` 录像标定任务；娱乐模式、自动下一局、周期近战和倒地爬行尚未接入。
- 当前第 4 张原图明确是“跳伞指挥官”，因此只等待 `E 发射`；非指挥官、需要 `LCTRL` 脱离的画面尚无独立样本，出现时会进入未知暂停。
- `SendInput` 是否被当前 Apex/反作弊环境接受，需要在目标 Windows 上验证；程序不提供反作弊绕过。
- 本地控制台只绑定 `127.0.0.1`，不会上传服务器，也不能直接从 Mac/手机访问；控制台没打开时任务照常运行。
- 若 DXGI 捕获黑屏，可把配置中的 `captureBackend` 从 `dxgi` 改为 `winrt`，并把安装依赖改为 `dxcam[winrt]` 后再试。
- DXcam 0.3.0 当前存在一个在 `release()` 清理 COM 指针时可能破坏进程的上游问题（issue #144）。每个 `start`/`live` 会话结束并完成日志落盘后会绕过 Python 的 COM 终结器，由 Windows 回收该进程的捕获资源。
