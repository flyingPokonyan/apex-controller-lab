# EA cache cleanup at the end of an account

After Apex exits, terminal lease cleanup selects **Menu → Help → App Recovery → Clear cache** through the same Help-menu path as Restart app, waits for the old EA window to close and a new readable home/login surface to settle, then runs the existing verified sign-out. It leaves EA at the login page for the next account. Already signed-out/pre-login sessions skip App Recovery. Startup repair, update handling, leftover-account sign-out and registration-to-game handoff retain their existing behavior, including Restart app.

The confirmation requires the dialog title "Restart to run App Recovery?" plus Clear cache and Cancel. That dialog is given 15 seconds. If it does not appear, the menu is closed with Escape (or a hamburger click when the key cannot be sent) and the full menu path is tried once more. The cache action never starts a second EA process while App Recovery may be restarting it. A menu or dialog that is still missing after that single retry is recorded and cleanup falls back to ordinary sign-out, so a TARGET_REACHED lease can close instead of pausing on `EA_CACHE_CLEANUP_FAILED` and later sitting in WAITING_FIX. An unchanged old window, a restart timeout, or a clear that already reached `REQUESTED` still pauses the same lease. The game result and target/fence are preserved; clearing or restarting EA is not sign-out evidence.

The existing `EA_SIGNING_OUT` checkpoint has an additional `eaCacheCleanup` field: `REQUESTED` is persisted before Clear cache is clicked; `COMPLETE` follows a verified restart; `SKIPPED_NOT_SIGNED_IN` records a pre-login page. A process interruption in `REQUESTED` requires operator inspection and does not automatically retry or assume success. After inspecting the desktop, the existing explicit resume action permits one new attempt. A completed clear is retained across sign-out retries. No checkpoint or runtime files should be deleted to recover this state.

Diagnostics distinguish `cache-clear-menu-missing`, `cache-clear-dialog-unconfirmed`, `cache-clear-requested`, `cache-clear-window-exited`, `cache-clear-restart-ready`, `cache-clear-skipped-login`, the App Recovery navigation steps `app-recovery-menu-open`, `app-recovery-help-missing`, `app-recovery-item-missing`, `app-recovery-requested`, and the existing `signed-out` event. The controller allowlist is `EA_STEPS` in `windows/apex_automation/diagnostic_schema.py`. Forge keeps a separate copy of that allowlist and must add every new step name or it will reject the events. Synthetic regressions cover menu selection, one dialog retry, confirmed transitions, sign-out fallback, failure retention and restart reconciliation; Windows UI behavior still needs an actual account-end observation after installation.

EA describes App Recovery as clearing EA App cache to address library, download and update issues. It may empty the download queue and may require signing in again. EA does not publish an exhaustive list of files/cookies/tokens removed; this workflow uses only the official UI and does not delete game directories or manually erase account data.

Sources: [EA cache recovery](https://help.ea.com/en/articles/technical-issues/clear-cache/), [EA download queue](https://help.ea.com/en/articles/platforms/download-and-play-ea-app-games/).
