# 托管 Runner 安全更新方案（待实现）

当前 `windows/update.cmd` 会在原目录执行 Git pull、安装依赖并等待键盘确认。它没有租约门禁、隔离安装、自检或回退能力，不适合由运行中的 Runner 自动调用。Forge 的 `configRevision` 是配置/令牌修订号，不能当作软件版本；当前 `0.5.1` 也不足以区分多个代码提交。

建议增加一个稳定的小启动器，应用按版本安装到不同目录，运行数据和机器私密配置留在固定目录。第一次需要每台机器手工安装启动器；以后由 Forge 指定经过测试的发布版本，机器在后台下载，账号结束后自动切换。此文是实现方案，当前代码不会更新机器。

## 发布和验证

Forge 保存发布清单：唯一 releaseId、实际 commit SHA、包下载位置、包 SHA-256、协议版本及最低启动器版本。控制端只选择已发布版本，不能直接追踪 main。建议签名发布清单并在启动器内置验证公钥，HTTPS、哈希与签名全部通过后才安装。

下载到临时版本目录，校验并解压；拒绝包内越界路径。为该版本建立独立 Python 环境或提供完整运行包，在没有真实游戏输入、没有领取账号的条件下执行导入、配置兼容和启动健康检查。失败保留旧版本，按退避重试，Forge 显示下载或验证失败原因码。

## 切换边界

领取下一账号之前，旧进程完成以下检查并退出：

1. 本地 checkpoint 没有占用租约、待收口操作或人工暂停原因，账号和 Apex 清理确认完成。
2. 查询服务端确认本机没有 `CLAIMED`、`RUNNING`、`COMPLETION_PENDING`、`EXPIRED_UNCONFIRMED` 租约；请求失败时不切换。
3. 与业务完成有关的游戏事件和最终证据报告已确认送达。诊断摘要使用稳定共享 outbox，可以由新版继续补传，不单独阻止更新。
4. 启动器持有跨版本机器锁，确认旧进程已退出、心跳/输入后台线程结束。原运行中的文件不会被覆盖。

仅“账号达到目标”等于安全切换是不够的：达到目标后仍可能需要停止游戏、退出 EA、补传报告和完成租约。Forge 持续展示旧版本、目标版本、等待账号结束/报告补传等状态，避免误认为更新失败。

## 原子切换与回退

启动器原子修改 `current` 指针，启动新版本；新版本在固定超时内报告健康并通过只读租约恢复检查，之后才允许领号。失败恢复旧指针，最多自动回退一次，避免无限循环。更新路径不删除 runs、checkpoint、outbox，也不改机器令牌。

第一版必须保持 checkpoint 和 outbox 向后兼容，禁止不可逆本机数据迁移。若新版本已领取租约，就不能靠杀进程进行回退：应停止领取后续账号，按现有收口/恢复规则处理当前租约，再回到安全边界切换。自动回退主要覆盖“尚未领号的新版本启动失败”。

先让 D135 验证一个发布周期，确认安全边界、断网重试、坏包拒绝、启动失败回退和报告续传，再把相同版本发给其他机器。首版建议控制台手动指定发布，机器自动执行；暂不做自动发布、任意远程执行或运行中热替换。
