# 观察会话清单

`observe` 只截图和识别，**不构造输入发送器，没有任何代码路径能发出按键或点击**。
可以一边正常游戏一边开着它。任何时候按 `F8` 或 `Ctrl+C` 结束。

## 开始前

```bat
cd apex-controller-lab
git pull
cd windows
observe.cmd
```

没有新依赖，不需要重跑 `setup.ps1`。确认终端打印出
`观察模式：只截图和识别，不会发送任何键盘或鼠标输入。` 再切回 Apex。

**不要跑 `start`。** 今晚只采样。

## 要覆盖的画面（按出现频率排，不按流程排）

### 1. 打完整一局，重点是结束之后 — 最高优先

目前 post-match 一张标定图都没有，而它每局都要走一次。需要覆盖：

- [ ] 被淘汰的瞬间 / 淘汰回放
- [ ] 观战队友的画面
- [ ] 选择离开比赛
- [ ] 赛后结算 / 经验结算
- [ ] 回到大厅

### 2. 局内三种状态要能分开 — 两条周期能力的闸门

局内有两条周期行为，动作不同，所以要能分辨：

| 状态 | 行为 |
|---|---|
| 存活 | 每 1–5 秒近战一次 |
| 倒地（被击倒未死亡） | 每 1–5 秒按一个方向键短促移动 |
| 死亡回放 / 观战 | 不做任何事 |

所以下面三种都要拍到，且**在同一次会话里**，得分才能直接对比：

- [ ] 存活、手持武器的常规 HUD
- [ ] 倒地（匹配模式才有；娱乐模式一般直接死）
- [ ] 死亡回放 / 观战

倒地那张最关键，也最难凑——需要真的被打倒。如果这局没被击倒过，
不用刻意去送，下次会话补也行；缺它的话倒地行为先不启用，近战照常。

### 2.1 各娱乐模式的开局交互

当前轮换里的模式各有不同的开局步骤，每个都是一条独立能力：

- [ ] 团队死斗：开局选武器的界面
- [ ] 控制：开局选武器的界面
- [ ] 控制：选出生点的界面（每次复活都要走）
- [ ] 子弹时间：确认它确实不需要选

### 3. 大厅 ↔ 模式面板 ↔ 准备

- [ ] 大厅停留几秒（拿模式名和主按钮的实测得分）
- [ ] 打开模式面板，**在面板上停留 5 秒以上不要马上点**
- [ ] 面板里滚动一遍，让当前轮换的**所有**娱乐模式都进过画面
- [ ] 选中"未上榜"，再回大厅

面板那一下很关键：配置里的 `unrankedMatchClick: [540, 835]` 经离线测量落在
**已锁定的排位赛卡片**上，真正的未上榜卡片在 y≈1000 附近。需要实测帧重新标定。

### 4. 登录过场视频

- [ ] 视频播放期间什么都不按，让它自己放完

这一段只是为了拿 `motion` 的实测值，用来定"过场视频"的判定阈值
（当前占位 0.02）。识别出来之后的策略是等它自己结束，不做主动探测。

### 5. 大厅流程指引（出现才做）

- [ ] 出现时先停留几秒
- [ ] **试一下按 `Esc`**，看能不能关掉
- [ ] 如果 Esc 没用，**试一下 `Enter`**

四张导览页现在用四个写死的坐标。如果 Esc 或 Enter 能通用关闭，四条规则可以塌成
一条，而且不再依赖坐标。这个只能手动试，程序测不出来。

### 6. 跳伞两屏（顺路）

- [ ] 跟队状态（画面上有"LCTRL 单独发射"）
- [ ] 脱离后状态（画面上有"E 发射 / LCTRL 重新加入小队"）

这两个的语义映射今天已经改过了，实测只是确认。

## 需要你手记的（程序采不到）

- [ ] 导览页 `Esc` / `Enter` 是否有效
- [ ] 结算/观战界面里"下一局"实际是按什么键
- [ ] 控制模式如果打了，出生点选择大概是什么交互

## 结束后

把整个 `windows\runs\<时间戳>\` 压缩发回。如果太大，**先只发这两个文本文件**：

- `observations-summary.json` —— 每个状态的实测得分分布、`separation`、OCR 耗时、运动量
- `observations.jsonl` —— 逐帧记录

我看完会指名要哪几张截图。截图已经做了去重（画面没变化的定时截图会跳过），
但打满一局仍可能有一两百张。
