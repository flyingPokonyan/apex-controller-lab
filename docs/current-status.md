# 现状汇总

> 截至 2026-07-30 深夜。这份文档回答两个问题：手上有哪些采集数据、能力闭环做到哪一步。
> 逐条能力的证据来源看[能力证据矩阵](capability-evidence.md)，这里只讲全局。

## 一句话

**闭环成立了：`20260730-200857` 从「继续」一路跑到结算，自动回大厅，又起了第二局。**
一整圈里需要动手的每一段都拿到了 `ACTION_CONFIRMED`，包括此前一直未验的跳伞长按和
结算返回序列。

成立不等于跑得稳。紧接着的 `20260730-215512` 用同一套配置跑了 16 分钟，暴露了三件事，
都已修：

- **观战把整个调度器冻住了。** 死了而队友还活着时 `SPECTATING` 反复进出，145 秒里进了
  5 次，触发会话级环检测；随后出现的结算页在 `TAB` 明晃晃写在屏幕上的情况下**被晾了
  78 秒**。环检测原来把任何画面的反复出现都当成环，包括运行器根本不动手的画面。
- **奖励页认不出来。** 它的标题「奖励」在 `x107-265`，落在 `titleCenter` 左边界 320
  之外；页面上没有「继续」也没有「领取」，只有左下角一句「ESC 返回」——而
  `reward-continue` 要的正是那两样，动作还配的是 `ENTER`。三条独立的原因，一条都不成立。
- **一局打完再按「准备」，队列三四秒后自己掉回大厅**，连着五次。原因未明，见下。

「闭环接上了」这个说法在 2026-07-30 白天的对话里出现过，指的是**执行路径**接上了
（能力集第一次真的被执行），不是整圈跑通了。现在整圈也跑通了，但两件事仍别混。

融合后的调度路径已有回归；真实 Apex 上仍要验证下面几个边界。

覆盖层没有塞进每 300ms 一次的快速识别循环：大厅、模式面板准备发输入前才扫一次，
未知画面持续 1.5 秒后才扫；10 类覆盖层共用一次全屏 OCR，再按文字块坐标恢复旧规则的
区域约束，阳性要连续命中两次才允许动作。全屏调用现在显式开启文字框检测；如果引擎
仍缺框，会降级为逐区域 OCR，而不是无限关闭安全门。欢迎/纪念页和公告只发 `ESC`，升级/奖励只发
`ENTER`，四个导览复用已有点击坐标。所有输入仍由同一个
`CapabilityDispatcher` 仲裁，OCR 失败则挡住大厅点击，而不是退化成盲点。

## 闭环的三段

一整圈是 `大厅 → 排队 → 传奇选择 → 跳伞机 → 对局 → 结算 → 大厅`，
其中需要动手的只有三段。

| 段 | 状态 | 证据 |
|---|---|---|
| 大厅 → 选模式 → 准备 → 排队 | ✅ **有实证** | `20260730-010042` 里 `ACTION_CONFIRMED lobby-start-match`，后置拿到 `LOBBY_QUEUEING` |
| 大厅停在别的模式 → 换回未上榜 | ✅ **有实证** | `20260730-215512` 885.8s：大厅读到「射击场」，点模式卡片 `[308,1215]` 开面板，点 `[493,1035]` 选未上榜，891.2s 回到 `LOBBY_READY_UNRANKED` |
| 传奇选择 → 跳伞机 | ✅ 成立（不需要动手） | 约一分钟静默，符合「能自动过去的就让它过」 |
| 跳伞机脱离 | ✅ **有实证** | `20260730-200857` 225.9s `ACTION_CONFIRMED dropship-detach → LAUNCH_READY`，`holdMs: 2000` 生效 |
| 对局近战 | ✅ **输入和效果有实证** | `20260730-191304` 发出 27 次，操作者确认有近战；落地时机不作为当前闭环验收项 |
| 结算 → 大厅 | ✅ **有实证** | `20260730-200857` 342.3s `ACTION_CONFIRMED post-match-return-lobby → LOBBY_READY_UNRANKED`，`TAB` → 1500ms → 长按 `SPACE` 2000ms 全程自动 |

操作者已经确认最后一段必须完整执行 `TAB` 后长按 `SPACE`。它现在是一条由结算页触发的
原子动作序列：不要求先识别中间页，也不会在其他未知画面上单独发送 `SPACE`。

## 三件已修的事

**一、环检测不该管运行器不动手的画面。** 原来的判据是「180 秒窗口里任何画面出现超过
4 次」，一旦成立就把**整个调度器**停住。观战、自由落体、读条这些画面反复出现是正常的
游戏节奏，不是环——环的定义应该是「运行器自己的动作在原地打转」。现在只有**挂着
`onState` 能力的画面**才计入；周期能力（近战）的画面同样不计，因为它本来就该重复。
真正的环——大厅↔模式面板来回——照样会被抓住，有测试盯着两边。

**二、认这句提示，而不是认每一页。** Apex 的全屏页统一在左下角 `x74-202 / y1325-1357`
写着「ESC 返回」。`215512` 一次跑里就有四页落在这上面：奖励页、排位之路、以及另外两张。
与其一页写一条规则，不如认这句提示本身——新增的 `fullscreen-esc-back` 覆盖层规则按它
自己写的键退出去。它必须满足两个条件才成立：排在所有专门规则之后，且**只在快速识别
认不出这一帧时**才算数。后一条不是保守，是必须：模式面板左下角写着同一句话，没有这道
闸门运行器一进面板就会退出去。传奇选择页实测没有这句提示，不会误伤。

**三、「补满」现在会被关掉。** 见下。

## 单人匹配

大厅左上角那个「补满」勾选框控制排队时要不要补进随机队友。关掉它就是单人匹配，
而单人匹配顺带解决了一个真实问题：**我死了但队友还活着时，运行器只能干等**——观战
没有任何能力（这是刻意的，提前退出会吃弃赛惩罚并丢掉排名经验）。单人局里我死了小队
就结束了，直接进结算页。

这一格是本项目第一个**不靠文字**的判据：勾没勾，OCR 两种情况读到的都是「补满」。
新增的 `pixelRequirements` 只量一件事——复选框内部有多少比例的像素亮过 0.75。勾是一个
固定的白色勾形，实测**勾上 0.284、没勾 0.000**（7 帧，跨三次会话），阈值取 0.15，
是这份字典里余量最大的判据。动作是 `toggle`：点第二下会把补满重新勾上，所以只允许一次
尝试，后置确认是「同一个大厅不再匹配 fill-on 规则」。

## 三个 bug 是同一种形态

`20260730-010042` 一次跑出三个 bug，它们的根因是同一件事：
**配置里写死的假定，和这台机器的实际情况不符。**

| bug | 假定 | 实际 |
|---|---|---|
| 训练场误按准备 | `[1280,1295]` 是「打开模式面板」 | 那一格写什么就干什么，训练大厅上写的是「准备」 |
| 近战没反应 | 近战绑在 `V` | 当时绑在 `N` |
| 跳伞没脱离 | `LCTRL` 点按 80ms 够 | 这个提示要长按 |

这三个的共同麻烦在于**它们在画面上和「输入根本没送到」长得一模一样**：动作发出去了，
截图上什么都没变。靠看截图区分不了，所以有了三样东西：

- `windows/probe-input.cmd` —— 发六个明显可见的动作，由人回答哪几个真的发生了。
  第一次跑的答案是「都有」，一句话排除了「合成输入进不去」这个方向；
- `enter-game.zh-CN.json` 的 `_keyBindings` —— 写明每个扫描码假定的是哪个键，
  有测试盯着「任何按键能力用到的码都必须在这段说明里出现过」；
- 按键能力自己的 `holdMs` —— 默认 `keyTapMs` 是给菜单点按用的，长按提示逐条声明。

## 剩余未知

| 未知 | 挡住什么 | 怎么拿到 |
|---|---|---|
| **一局打完再排队，队列三四秒就掉回大厅** | **连着跑** | 见下 |
| 补满关掉之后队列还掉不掉 | 同上 | 下次 play 自然验证 |
| 控制模式的「还活着」判据 | 控制模式里的近战 | 需要一张死亡/重生帧 |
| 修正后的登录后清障串 | 从桌面冷启动 | 新闻页和奖励页已成为真实规则样本，下次 play 自然验证 |

排队掉线是现在唯一挡住「连着跑」的东西，`20260730-200857` 和 `20260730-215512`
两次都出现，形态完全一致：

| 时刻 | 画面 |
|---|---|
| 878.6s | 点「准备」 |
| 879.0s | `LOBBY_QUEUEING`（主按钮读到「取消」，截图核对无误，不是 OCR 认错） |
| 882.2s | 又读到「准备」——队列自己没了，期间运行器一次输入都没发 |

规律是**每次会话的第一次排队都成，一局打完回来之后的每一次都掉**。最像的解释是
上一局的奖励/结算流程还没走完，游戏这时接受了排队请求又在几秒后作废它——奖励页正是
这一版才被认出来的那一页。所以先不动排队逻辑：**修好奖励页很可能顺带修好它**，
下一次 play 会给出答案。如果奖励页清干净了队列还掉，再单独查。

控制模式死亡/重生帧仍要在实际玩到该模式时获得，但它是扩展，不挡主线。

无法主动制造、碰到再补：断连弹窗、匹配惩罚提示（必须归入人工暂停）。

## 不再靠专门采集

主线三个待验项和冷启动清障不再要求先开一次专门的采集任务；下次正常跑 `play` 会自己
给答案。控制模式那一项则在实际遇到时由同一套自动留证补上：

- `CapabilityPilot` 现在会**给自己不认识的画面留证**：状态连续 8 秒是 `None` 就存一帧，
  每段只存一次（读条也会被拍到，这就是宽限给到 8 秒的原因）；
- 跳伞和近战的修改，在同一次跑里就会自证；
- 已知欢迎、纪念、活动、奖励、升级和四个导览已经接入 `play`，新变体认不出来也会留证；
- 状态变化本来就会存截图。

换句话说，从这一版开始，**「跑一次」和「采一次」是同一件事**。

## 下一步

`update.cmd` → `play.cmd`，从「继续」开始正常跑，并且**这次让它连着跑几局别停**。
一次跑完能同时回答四件事：

- 奖励页会不会被 `ESC` 自动关掉（`ACTION_SENT dismiss-esc-back`）；
- 关掉奖励页之后，一局打完再排队还掉不掉；
- 「补满」会不会在第一次进大厅时就被点掉（`ACTION_CONFIRMED lobby-disable-fill`）；
- 死了而队友还活着时，结算页还会不会被环检测晾着——这次它不该再出现
  `CYCLE_DETECTED`，因为观战不再计入。

娱乐模式暂缓，不在这一轮范围内。
