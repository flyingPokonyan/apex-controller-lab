# Apex Controller Lab：本地菜单自动化验证与 Windows 接入清单

> 文档版本：0.1
> 日期：2026-07-27
> 当前状态：浏览器流程已实现，尚未连接真实 Apex
> 停止边界：完成英雄与可选枪械选择后停止，不执行移动、瞄准或战斗

## 1. 当前需求

当前阶段只覆盖以下菜单流程：

```text
启动继续页
  → 点击“继续”
  → 识别并关闭可选活动弹窗
  → 确认进入大厅
  → 打开模式面板
  → 选择预设娱乐模式
  → 验证大厅中的模式名称已经更新
  → 点击准备/开始游戏
  → 等待英雄选择页
  → 选择首选英雄，必要时选择备选英雄
  → 若出现枪械/配装页，选择预设枪械
  → 完成并停止
```

当前不做跳伞、方向控制、移动、瞄准、开火、搜集或自动战斗。

## 2. 为什么不能只有固定坐标

在分辨率、DPI、语言、UI 缩放和显示模式完全固定时，菜单点击点位通常比较稳定。但下面这些情况仍会改变点击结果：

- 启动页还没有加载完；
- 偶发活动页覆盖了大厅；
- 上一次退出时停在不同子页面；
- 模式面板打开失败；
- 匹配按钮暂时不可用；
- 已进入匹配，但程序仍继续点击大厅坐标；
- 英雄被其他玩家先选；
- 当前娱乐模式没有枪械选择页。

因此动作模型必须是：

```text
截图
  → 只检测当前状态允许出现的局部锚点
  → 置信度达到阈值
  → 点击归一化坐标或发送确认键
  → 再截图验证目标状态
  → 超时则停止，不盲点下一步
```

## 3. 浏览器版本已经验证什么

首页 `/` 提供一个完全在 DOM 内运行的假游戏画面和状态机。它已经实现：

- `CONTINUE` 启动页识别；
- `EVENT_MODAL` 可选活动弹窗分支；
- `LOBBY` 大厅确认；
- `MODE_PANEL` 模式选择及返回大厅后的二次验证；
- `MATCHMAKING` 匹配等待；
- `LEGEND_SELECT` 首选/备选英雄分支；
- `LOADOUT_SELECT` 可选枪械页分支；
- `MATCH_READY` 出生前停止边界；
- 每次捕获、识别、输入、状态变化的 JSON 运行记录。

浏览器检测器读取页面的模拟状态标记，输入发送器只改变 React 状态。它证明的是编排逻辑，不证明真实 Apex 能被截图或接收模拟输入。

页面默认使用 `0.5×` 慢速演示，完整流程约 18 秒。需要仔细观察每次状态变化时，可以选择 `0.25×`；`2×` 和 `4×` 主要用于快速回归测试。

## 4. Windows 版的模块替换

```text
浏览器版本                         Windows 版本
DOM 模拟状态标记          →       Windows.Graphics.Capture 画面帧
页面内锚点判断            →       局部模板匹配 / OCR
React 状态变化            →       Windows 鼠标键盘或手柄输入适配器
内存中的运行日志          →       runs/<run-id>/actions.jsonl
模拟截帧计数              →       runs/<run-id>/screenshots/*.png
```

场景状态机和失败停止规则保持不变。

## 5. 需要从目标 Windows 采集的画面

首次标定固定以下环境：

```json
{
  "resolution": "1920x1080",
  "dpiScale": 1.0,
  "language": "zh-CN",
  "displayMode": "borderless",
  "uiScale": "fixed"
}
```

然后保存无压缩 PNG：

```text
calibration/raw/
├── 01-continue.png
├── 02-event-modal.png          # 遇到时再采集
├── 03-lobby-clean.png
├── 04-mode-panel.png
├── 05-lobby-mode-selected.png
├── 06-matchmaking.png
├── 07-legend-select.png
└── 08-loadout-select.png       # 仅有该页面的模式
```

每张图同时记录：游戏窗口左上角、窗口客户区尺寸、Windows DPI、游戏语言、显示模式和采集时间。

不要只裁按钮。保留一张完整原图，再从原图中选取局部锚点，例如：

- “继续”文字和它旁边的固定图标；
- 活动页右上角关闭按钮及弹窗边缘；
- 大厅顶部固定导航和模式名称区域；
- 模式卡片标题及选中高亮；
- 英雄选择页标题与候选头像区域；
- 枪械页标题及目标配装卡片。

## 6. 推荐的状态识别方式

第一版不需要训练视觉模型，使用状态限定的局部模板匹配即可：

```text
已知可能状态集合
  → 对 2 到 4 个固定 ROI 分别匹配
  → 多锚点加权得到状态置信度
  → 连续两帧超过阈值才确认
```

建议阈值从 `0.90` 开始标定。文字会因反锯齿、语言和分辨率变化产生差异，优先匹配图标、边框和稳定布局；OCR 只用来确认模式名、英雄名或配装名。

固定点击位置保存为相对游戏客户区的归一化坐标：

```json
{
  "continue": { "x": 0.500, "y": 0.760 },
  "dismissEvent": { "x": 0.923, "y": 0.105 }
}
```

文档中的数值仅对应浏览器假画面，不是 Apex 真实点位。真实坐标必须在目标 Windows 上重新标定。

## 7. 英雄与枪械分支

英雄不要只配置一个：

```json
{
  "legendPreference": ["首选英雄", "备选英雄 1", "备选英雄 2"],
  "selectionTimeoutMs": 8000
}
```

如果目标头像显示已占用、无法高亮或确认后名称不匹配，就按顺序尝试备选。全部失败时停止，不随机点击。

枪械选择必须是可选步骤：

```text
英雄确认后
  → 最多等待 N 秒识别 LOADOUT_SELECT
  → 出现则选择并验证
  → 未出现但检测到 MATCH_READY/出生准备状态则正常跳过
  → 两者都未出现则失败停止
```

不同娱乐模式、限时模式或版本更新可能使用不同配装页面，不能假设团队死斗与其他模式完全相同。

## 9. Windows 接入验收顺序

1. 先对保存的 PNG 做离线识别，要求每张图状态分类正确。
2. 用自建 Windows 假界面验证真实窗口捕获和输入适配器。
3. 只连接 Apex 菜单，逐步人工确认每次动作；不要第一次就运行全流程。
4. 先验证继续页和关闭弹窗，再验证大厅模式选择。
5. 最后接英雄和枪械选择，并保留每一步前后的截图。
6. 任一步骤置信度不足、窗口失焦或超时都立即释放输入并停止。

真实游戏接入不读取或修改内存、不注入进程、不绕过反作弊。使用前需要接受账号规则与自动化风险；如果游戏或平台禁止这种自动化，应停留在浏览器/自建测试环境。
